# 🐤 小目标 · 部署指南

「小目标」是纯前端 + Node 本地服务器的网页 App，支持 4 种部署方式，从最简单到最强 API 保护。

---

## 方式一：本机使用（最简单）

```bash
node server.js            # 默认端口 3111
# 或
./start.sh                # 或 start.bat (Windows)
```

打开 `http://localhost:3111` 即可。

## 方式二：局域网使用（手机/平板）

```bash
node server.js
# 会打印出局域网地址，如 http://192.168.1.5:3111
```
手机连同一 Wi-Fi，浏览器打开该地址。
**API 保护**：浏览器把 Key 放请求头发给本机 server，由 server 转发给 AI 供应商 —— Key 不出你的设备。

## 方式三：公网访问（内网穿透，可远程打卡）

任选其一（服务器启动后执行）：

```bash
cpolar http 3111
ngrok http 3111
cloudflared tunnel --url http://localhost:3111
```

⚠️ **公网必须开启护栏**（否则你的代理会被别人当免费中转白嫖）：

```bash
# 启动时带环境变量
ACCESS_TOKEN=你的秘密令牌 \
ALLOWED_DOMAINS=api.deepseek.com,open.bigmodel.cn \
AI_KEY=sk-你自己的key \
RATE_LIMIT=30 \
node server.js
```

### 护栏说明

| 环境变量 | 作用 | 必开场景 |
|---------|------|:-------:|
| `ACCESS_TOKEN` | 访问令牌：前端请求必须带 `X-Access-Token`，否则 401 | ✅ 公网 |
| `ALLOWED_DOMAINS` | 目标域名白名单（逗号分隔），防止被当成任意 URL 代理(SSRF) | ✅ 公网 |
| `AI_KEY` | **服务端持 Key 模式**：忽略前端传来的 Key，统一用服务器自己的 Key —— 别人永远拿不到你的 Key | ✅ 公网 |
| `AI_ENDPOINT` | 服务端默认目标端点（可配合 AI_KEY 使用） | 可选 |
| `RATE_LIMIT` | 每分钟每 IP 的代理请求上限（默认 60） | ✅ 公网 |

> 前端请求示例（启用 ACCESS_TOKEN 时，前端会在 AI 配置里加一个"访问令牌"输入框）：
> ```
> POST /api/proxy
> X-Access-Token: 你的秘密令牌
> X-Target-Endpoint: https://api.deepseek.com/chat/completions
> Authorization: Bearer 你的API Key
> ```

## 方式四：纯静态托管（GitHub Pages / Netlify 等）

把 `app/` 目录整个推上去即可。**注意**：静态托管没有 server.js，前端自动回退"直连"模式 —— 此时 API Key 直接发给供应商，需要供应商支持 CORS（DeepSeek/智谱/通义/Kimi 均支持）。适合个人低风险使用，公网共享场景请用方式三。

---

## 环境要求
- Node.js ≥ 14（本机/局域网模式需要；纯静态托管不需要）
- 手机安装：Safari/Chrome 打开后"添加到主屏幕"即为 PWA，可离线使用

## 常见问题

**Q：AI 拆解报"连接失败"？**
A：先到「更多 → AI 配置」点"测试连接"。检查：Key 是否正确、供应商是否选对、是否走代理（本地 server 需运行）。

**Q：为什么建议开启"本地代理"？**
A：浏览器直连供应商受 CORS 限制且 Key 明码在网络中；本地代理由你的 server 转发，Key 不出设备，且支持 Ollama 等非 HTTPS 端点。

**Q：Ollama 怎么用？**
A：选 Ollama 预设，端点填 `http://localhost:11434/v1/chat/completions`（或局域网 IP），无需 Key。需与本机在同一网络。

**Q：数据在哪？会丢失吗？**
A：全部存浏览器 localStorage（`xiaogubiao_v1`）。「更多 → 导出数据」可备份 JSON。换设备/清缓存前请先导出。
